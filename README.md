# PPT 知识点提取复习助手

把老师的 PPT 或 PDF 课件，变成一份能直接背的期末复习笔记。

导入课件 → 自动剔除页脚、页码、致谢页这些废话 → 把真正会考的内容分类成
**核心定义 / 公式 / 结论 / 易错点 / 简答考点** → 输出两种 Markdown：
考前背诵用的**精简复习版**，和能直接拖进 XMind、幕布的**思维导图大纲版**。

全程本地运行，课件不会离开你的电脑。

---

## 这个工具解决什么问题

期末周的典型场景是这样：一章课件 80 页，真正会考的可能是 20 句话，
但它们散落在各个角落里，中间夹着目录页、过渡页、"谢谢观看"和一堆图片。
人工翻一遍要一两个小时，翻完还不记得哪句是重点。

这个工具把"翻"这一步自动化了：它按句子的措辞判断这是定义、是公式、
是易错提醒还是简答考点，然后按类别归位，让你一眼看到"这章到底要背什么"。

它**不**做的事也要说清楚：它不替你理解知识，也不猜老师出题。
它只是把课件里像考点的句子挑出来、分好类、去掉噪音。最终判断仍然是你的事。

## 效果示例

输入 `demo/计算机网络_第3章_传输层.pptx`（10 页，含页脚、页码、重复页眉、致谢页），
输出节选：

```markdown
## 核心定义（5 条）

- ★ 传输层是指为两台主机中的应用进程提供端到端通信服务的层次。（P3）
- ★ 端到端通信是指数据从发送方进程直接送到接收方进程，中间网络不拆开看。（P3）
- ★ 端口是指传输层用来标识应用进程的 16 位编号。（P4）

## 公式（2 条）

- 吞吐量 = 窗口大小 / 往返时间 RTT（P7）
- 信道利用率 U = 吞吐量 / 带宽（P7）

## 易错点（2 条）

- 易错点：流量控制是端到端的，拥塞控制面向整个网络，两者不要混淆。（P9）
- 注意区分：流量控制靠接收窗口，拥塞控制靠拥塞窗口。（P9）
```

完整的输出在 `demo/sample_output/` 里，可以直接打开对比。

## 安装

需要 Python 3.10 或更高版本。

```bash
git clone <你的仓库地址>
cd ppt-review-helper
pip install -r requirements.txt
```

依赖只有两个，都是纯 Python 包，没有需要编译的东西：

| 依赖 | 用途 |
| --- | --- |
| python-pptx | 读取 .pptx 课件 |
| pypdf | 读取 .pdf 课件 |

## 使用

最常用的三条命令：

```bash
# 生成复习笔记 + 思维导图（默认行为）
python -m ppt_review 课件.pptx

# 指定输出目录
python -m ppt_review 课件.pdf -o 我的笔记

# 只要名词解释，应对名词解释题型
python -m ppt_review 课件.pptx --only 名词解释
```

全部参数：

| 参数 | 说明 |
| --- | --- |
| `input` | 课件路径，支持 .pptx 和 .pdf |
| `-o, --outdir` | 输出目录，默认 `output/` |
| `--only` | 只输出某一类：`名词解释` / `简答` / `公式` / `易错点` / `结论` / `全部`（默认） |
| `--format` | `all`（默认）/ `review`（只出复习笔记）/ `mindmap`（只出思维导图） |
| `--title` | Markdown 一级标题，默认用文件名 |
| `--stdout` | 只打印到终端，不写文件 |

几个真实场景：

```bash
# 考前两小时，只要简答题
python -m ppt_review 第5章.pptx --only 简答

# 通读一遍，直接在终端看，不落文件
python -m ppt_review 复习.pdf --stdout

# 把思维导图大纲导出来，再拖进 XMind
python -m ppt_review 第3章.pptx --format mindmap -o 导图
```

## 项目原理

整条流水线是四个模块，每个模块只干一件事，可以单独替换：

```
课件文件
   ↓
[ parsers.py ]   文件解析：把 pptx / pdf 读成统一的「页 → 文本块」结构
   ↓
[ cleaner.py ]   文本清洗：去掉页码、页脚、重复页眉、致谢页，接回被排版拆断的句子
   ↓
[ extractor.py ] 知识点提炼：按措辞把每句话归类成五类考点，并打 ★/☆ 标记
   ↓
[ renderer.py ]  输出：渲染成「精简复习版」和「思维导图大纲版」两份 Markdown
```

### 怎么判断一句话属于哪一类

分类用的是关键词规则，而不是机器学习模型。这么选的原因很实际：
规则可读、可改。你觉得老师爱考别的东西，直接改 `extractor.py` 顶部的
关键词列表就行，不需要重新训练任何东西。

大致规则：

| 类别 | 判断依据 | 例子 |
| --- | --- | --- |
| 公式 | 含数学符号，或形如 `X = Y` 的等式 | `吞吐量 = 窗口大小 / RTT` |
| 易错点 | 含"易错、误区、常见错误、切忌、容易混淆" | `易错点：两者不要混淆` |
| 核心定义 | 含"是指、称为、定义为、是一种" | `端口是指…的 16 位编号` |
| 简答考点 | 以问号结尾，或含"简述、试述、比较、列举、说明" | `简述 TCP 与 UDP 的区别。` |
| 结论 | 含"因此、所以、结论、可知、定理、性质" | `因此拥塞控制站在网络整体角度` |

### ★ 和 ☆ 是怎么打出来的

两个依据，优先看第一个：

1. 课件自己标了。出现"重点、必考、考点、掌握"打 ★；出现"了解、选学、补充"打 ☆。
2. 课件没标时看重复度。如果某个术语在全篇出现 3 次以上，说明老师反复讲，打 ★。

### 已知的局限

说清楚边界，比夸大能力有用：

- **扫描版 PDF 和图片版 PPT 读不出字**。这类文件本质是图片，要先做 OCR。
  工具遇到空结果会明确提示，不会假装读到了内容。
- **图片形式的公式读不出来**。很多老师把公式截图贴进 PPT，那种情况目前无解。
- **规则分类会有误判**。比如"因此…说明…"这种句子既像结论又像简答，
  工具会按固定优先级归类，不一定和你的判断一致。
- **不做 OCR、不调用任何大模型**。这是刻意的：为了让课件不出本机，
  也为了让依赖保持在两个包。如果你想要语义级提炼，可以在这个流程后面
  接一个自己的模型，`extractor.py` 输出的结构化结果可以直接喂给模型。

## 参与贡献

欢迎提 Issue 和 PR。几个明确需要帮忙的方向：

- 补充各学科的关键词规则（尤其文科类，现在的规则偏理工科）
- 支持 .docx 课件（`parsers.py` 里加一个函数即可）
- 支持表格里的文字提取

提交前请确认 `python -m ppt_review demo/计算机网络_第3章_传输层.pptx --stdout`
能正常跑通。
